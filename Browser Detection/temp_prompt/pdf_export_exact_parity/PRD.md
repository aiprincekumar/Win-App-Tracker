# Product Requirements Document (PRD)

> **Task ID:** `TASK-PDF-EXPORT-EXACT-PARITY-001`  
> **Initiative:** PDF Export Exact Parity Overhaul  
> **Target Audience:** Privacy-Conscious End Users, Productivity Observers, System Auditors  
> **Document Status:** Authoritative Architectural Requirement  

---

## 👤 1. User Personas & Problem Scenarios

### 1.1 Persona: Executive Productivity Observer ("Priya")
- **Profile:** Wants a clean, professional, two-page PDF report to review her weekly focus, top visited domains, and media consumption.
- **Pain Point:** When she clicks "Print / Save as PDF", she gets a messy, distorted printout of the dashboard sidebar and broken layouts, with media analytics missing or jumbled across multiple pages. The downloaded HTML report looks gorgeous, but she cannot get that same layout into a PDF to share or archive.
- **Desired Outcome:** Clicking "Print / Save as PDF" should print the exact same pristine, formatted document as the HTML export, beginning with Time Tracking on Page 1 and seamlessly transitioning to Media Analytics on Page 2.

### 1.2 Persona: Offline Archival Auditor ("Rahul")
- **Profile:** Needs reproducible, audit-grade PDF records of website usage and media sessions that can be printed or digitally signed.
- **Pain Point:** Unpredictable page breaks and cut-off tables make the printed output look amateurish and incomplete.
- **Desired Outcome:** Predictable pagination, clear table headers on every page, atomic metric cards that never split across page boundaries, and checksum verification badges.

## 📋 2. Functional Requirements (FR)

| ID | Category | Requirement Description | Priority |
| :--- | :--- | :--- | :---: |
| **FR-01** | **Print Parity** | The PDF export (`#btnPrintPdf`) MUST render the exact document output generated by `generateExecutiveDigestHtml`, ensuring 100% visual and telemetry parity with the standalone HTML digest. | **P0 (Must)** |
| **FR-02** | **Isolated Iframe Printing** | The print engine MUST use an isolated hidden `<iframe>` to load and print the digest document without exposing the user to layout shifts, unstyled flash, or live dashboard DOM interference. | **P0 (Must)** |
| **FR-03** | **Two-Part Structure** | The printed output MUST adhere to a strict two-part sequence: Part 1 (Time Tracking & Circadian Focus) followed by Part 2 (Media Analytics & Streaming Telemetry). | **P0 (Must)** |
| **FR-04** | **Strict Page Break** | Part 2 MUST strictly start on a new page via CSS page-break rules (`break-before: page; page-break-before: always;`). Part 1 and Part 2 must never collide on the same page. | **P0 (Must)** |
| **FR-05** | **Live Data Hydration** | `triggerPrintPdf` MUST extract the complete set of live metrics from the dashboard DOM and runtime state (including 10 Time Tracking KPIs, 7x24 Chrono Heatmap, 10 Media KPIs, domain table, and media history). | **P0 (Must)** |
| **FR-06** | **Iframe Lifecycle & Cleanup** | The hidden iframe MUST be created idempotently, loaded cleanly, focused, printed, and safely cleaned up or detached after printing to prevent DOM pollution or memory leaks. | **P1 (Should)** |
| **FR-07** | **Resilient Fallback** | If iframe execution is blocked by security boundaries, the system MUST fall back gracefully to a dedicated print container or direct print without throwing fatal unhandled exceptions. | **P1 (Should)** |
| **FR-08** | **Toast & Status Feedback** | The system MUST provide clear user feedback (bilingual EN/HI toasts) indicating that the PDF/print dialog is being prepared. | **P2 (Nice)** |

## 📜 4. INVEST-Compliant User Stories

### Story 1: Exact HTML-PDF Export Parity
- **As a** dashboard user,
- **I want** the PDF export to look exactly like the Standalone HTML Digest,
- **So that** I have a clean, professionally formatted summary of my activity without web application clutter.
- **Acceptance Criteria (Given-When-Then):**
  - **Given** the dashboard is populated with tracking and media data,
  - **When** I click "Print / Save as PDF" in the export menu,
  - **Then** the print preview dialog displays the standalone Executive Digest document with exact matching styles, fonts, cards, and tables, rather than the raw dashboard UI.

### Story 2: Clean Two-Page Separation
- **As a** productivity reviewer,
- **I want** Time Tracking on Page 1 and Media Analytics on Page 2,
- **So that** each domain has its own dedicated, uncrowded page in the PDF.
- **Acceptance Criteria (Given-When-Then):**
  - **Given** an export containing both tracking and media history,
  - **When** the print preview is generated,
  - **Then** Page 1 displays the Executive Header, 10-KPI Tracking Grid, Chrono Heatmap, Activity Donut, and Domain Table,
  - **And** Page 2 strictly begins with the Media Analytics section title and 10-KPI Media Grid, with zero bleed onto Page 1.

### Story 3: Complete Telemetry Hydration
- **As an** auditor,
- **I want** real-time metrics reflected in the printed PDF,
- **So that** I don't see default or empty placeholder values in my reports.
- **Acceptance Criteria (Given-When-Then):**
  - **Given** active session data in the dashboard,
  - **When** I trigger a PDF print,
  - **Then** all 10 tracking KPI cards, all 10 media KPI cards, and the 7x24 heatmap cells reflect the exact values displayed on the dashboard tabs.

## 🎯 5. MoSCoW Feature Prioritization

- **Must Have (P0):**
  - Isolated iframe print execution using `generateExecutiveDigestHtml`.
  - Full telemetry extraction for both tracking and media in `dashboard.js`.
  - Strict two-part CSS pagination with page break before media section.
  - Universal Rule 28 compliance and UTF-8 with BOM preservation.
- **Should Have (P1):**
  - Fallback mechanism for restricted iframe environments.
  - Idempotent iframe element recycling and post-print cleanup.
  - Table header repetition across pages (`thead { display: table-header-group; }`).
- **Could Have (P2):**
  - Print status animation or loading indicator on the export menu button.
  - Offline checksum indicator in print footer.
- **Won't Have (Out of Scope):**
  - Server-side headless PDF rendering (Puppeteer/Chrome PDF API) — must remain 100% client-side offline.
  - Custom user-configurable page reordering or section omission.
